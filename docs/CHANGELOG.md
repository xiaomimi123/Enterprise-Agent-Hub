**桌面启动器不再依赖安装脚本；模型网关限流导致员工同步失败（接入器 0.5.2）**
- 桌面启动器：你指出员工让 WorkBuddy 代跑接入时桌面上不会有快捷方式。原因是建快捷方式只写在安装脚本里，而 WorkBuddy 常常直接运行接入器的 `setup`，而且它会拦截建快捷方式要用的 COM。现在由接入器在接入时把双击启动器直接复制到桌面（用系统接口取桌面位置，不用 COM；桌面上已有同名、但不是我们放的文件时不覆盖；放不了时记入应用健康）；员工自己运行安装脚本时会换成正式快捷方式并删掉这个副本。agent 通过中枢打开应用时，回复里会请它告诉员工「以后双击桌面上的图标打开，关掉 agent 也不会影响它」；接入方式页「发给员工的话」里给 agent 的提示也加了这一句。
- **模型网关限流（这次排查时顺带发现，影响正在用的员工）**：员工领取配置接口间歇返回 502，原因是中枢调模型网关管理接口时被限流（HTTP 429）。工作台每个任务都会运行一次 CodeBuddy CLI，而 CodeBuddy 每次运行都会重启中枢的桥、重新领取配置（林杰 4 分钟领了 19 次），每次领取又要调网关好几次，所有请求都来自中枢一个 IP，撞上了默认的每 3 分钟 180 次。修复：网关上限调到 6000（`NEWAPI_API_RATE_LIMIT`）；中枢遇到 429 等一下再试两次；接入器的桥 10 分钟内同步过就不再领取（心跳和成果转发照常）；接入时同步失败只有真是登录问题才重新弹浏览器登录，中枢临时出错不再误弹。
- 验证：后端 376 项通过（新增：桌面放启动器 / 不覆盖员工文件、打开应用的提示、10 分钟内不重复领取、临时出错不弹登录、429 重试）；在临时目录真实跑通「接入器放副本 → 安装脚本建正式快捷方式并删掉副本」；重启模型网关后确认新上限生效（6000 / 180 秒），端到端 20 项通过，之后没有新的 502。
