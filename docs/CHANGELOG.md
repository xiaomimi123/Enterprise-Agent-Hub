**安装命令加 `-NoProfile`（一台电脑上粘贴命令只出现「拒绝访问。」）**
- **现象**：员工在 cmd 里运行 `powershell -NoExit -ExecutionPolicy Bypass -c "irm …/install.ps1 | iex"`，只输出一行「拒绝访问。」，没有任何 `[PASS]`；该电脑没装第三方杀毒，其他几个人都正常
- **排查**：中枢访问日志里这次失败**到过中枢**（`install.ps1` 200），但之后没有 `preflight.ps1` / `bundle/manifest.json` 请求，说明脚本刚开始执行就被拒；在那台电脑上 `powershell -NoProfile -Command "echo ok"`、`-ExecutionPolicy Bypass`、`irm` 下载、写临时目录、`Get-ExecutionPolicy -List`（CurrentUser=RemoteSigned）、FullLanguage 全部正常；换成 `powershell -NoProfile -Command "irm …/install.ps1 | iex"` 正常安装
- **结论（没有完全确认）**：原命令和能用的命令差在「是否加载用户 PowerShell 配置文件」「`-NoExit`」「`-ExecutionPolicy Bypass`」，最可能是这台电脑的个人配置文件有问题；没跑 `powershell -Command "echo ok"`（会加载配置文件）去坐实
- **改动**：标准安装命令统一改成 `powershell -NoProfile -NoExit -ExecutionPolicy Bypass -c "…"`：控制台「接入方式」页（`Connect.tsx` 的安装命令和自检命令）、`agent/install.ps1` 和 `agent/preflight.ps1` 头部注释、`agent/README.md`、`docs/员工电脑安装说明.md`（另加一条「只出现『拒绝访问。』」常见问题）、`docs/测试流程-WorkBuddy浏览器插件.md`。保留 `-NoExit`（Win+R 运行时窗口不会一闪而过）；以后员工机上的个人配置文件（conda、美化插件等）都不会干扰安装

## 2026-10-29（总览与成员页数据不一致）

**成员页「最近活跃」和总览「实时活动」对不上：统一口径**
- 现象（用户截图）：周润鑫在成员页显示「离线、8 天前」，总览实时活动里却有「员工端 agent 登录并同步配置」「打开应用」都是 1 小时前

## 2026-10-28（升级老安装）

**老安装升级：修掉「升级会悄悄删掉 CodeBuddy CLI」；整理升级路径**

ode`），而底座包升级会整体替换 `runtime
ode`，升级后 CodeBuddy 的 `codebuddy.cmd` 和包都没了（只剩 `node.prev`），员工要重新装。用隔离目录还原了老安装（便携 Node + npmmirror 装的 CodeBuddy 2.177.1、没有 `BASE_VERSION`），对着真实中枢重新运行安装脚本，复现了丢失

**Mac 上安装的复盘（`install.sh` 在 agent 里卡死等）**
- 来源：你在另一台 Mac 上让 WorkBuddy 代跑安装后写的复盘。逐条对照代码和服务验证：
  - **属实，已修：脚本在非交互时卡在提问**。`confirm()` 只判断 `/dev/tty` 能否打开，而 agent 拉起的子进程继承了控制终端，能打开却没有人回答，`read` 永远等。又因为脚本是 `curl | sh`（stdin 是管道），复盘建议的 `[ -t 0 ]` 对真实员工恒为假，不能用。改为：要求**标准输出是终端**（agent 会捕获输出）、且没有 `CI` / `CLAUDECODE` / `CODEBUDDY_CODE` / `WORKBUDDY_*` 环境变量，才从 `/dev/tty` 询问；否则跳过，并打印可直接复制的 `HUB_INSTALL_TOOLS=yes curl ... | sh`。
  - **属实，已修：PATH 前置 `~/.local/bin` 让别的工具链留下的 alpha 版 Node 压过正常的 Node**。改为追加；检测到预发布版 Node 会提示；装完 CodeBuddy 后用 `--version` 验证并给出写入 `~/.zshrc` 的命令；脚本开头提示首次登录要改密码；结尾提示 CodeBuddy 的 `/login`。
  - **属实但根因判断不对：控制台一直「正在登录…」**。前端请求用的是相对路径 `/api`，从中枢地址打开时是同源，CORS 白名单不起作用；在预览面板里的页面来源不是中枢，`/api` 根本没转到中枢，放宽 CORS 也没用。因此**没有采纳「放行 localhost:* / null」**：带凭证的跨源放行会扩大攻击面，而且 `redirect_uri` 必须和 Casdoor 里登记的一致，不能按 Host 动态生成。实际做的：前端请求加 20 秒超时和明确提示（「请直接用浏览器打开中枢地址」），不再无限转圈。
  - 未采纳/暂缓：工作台自动选中 Codex 而非 CodeBuddy（需看工作台适配器选择逻辑，另议）；`/healthz`。
- 验证：`sh -n` 语法通过；用桩命令模拟：捕获输出时跳过提问并打印复制命令、`HUB_INSTALL_TOOLS=yes` 走安装、设置 `WORKBUDDY_*` 时跳过；`tsc`、oxlint 通过，已重建前端并确认服务端发出新脚本。**没验证**：真实终端里的交互询问（这里没有 tty），Mac 上完整重跑。
