# 计费与额度

## 原则

**中枢只为经过中枢的东西计费，模型 token 谁提供谁计费。** 员工用 Hermes、WorkBuddy、Cursor 还是别的 agent，中枢都不需要为它单独改计费：

| 计量对象 | 谁来计 | 适用范围 |
|---|---|---|
| 中枢资源：工具调用（检索、技能、生成派发）、GPU 用时、出图张数、视频条数 | 中枢（审计日志 + GPU 任务队列） | 所有 agent |
| 模型 token | 「中枢模型」：New API 按员工专属 key 计量；「自带模型」：agent 那家产品自己的积分 | 只有中枢模型计入控制台 |

## 岗位包上的两个设置

- **模型方式**（`model_mode`）
  - 中枢模型：员工领取配置时，中枢下发 New API 的员工专属 key（Hermes 走这条），token 和花费进「用量与成本」，额度是「每人月模型额度」
  - 自带模型：员工用 agent 自带的模型和积分，中枢不发 key、不统计 token
- **GPU 额度**（`gpu_quota_minutes`）：每人每月 GPU 分钟数，0 表示不限。按生成任务的实际运行时长累计（正在跑的算到当前），当月用完后新任务被拦截：MCP 返回提示，HTTP 接口返回 403，并记一条拦截审计

另有并发限制：每人最多同时 `HUB_GPU_MAX_PENDING_PER_USER`（默认 3）个未完成的生成任务，超出时 HTTP 返回 429。

## 模型与额度如何落到员工 key（中枢模型）

员工每次领取配置（接入器 sync、chat、WorkBuddy 启动桥接）时，中枢按岗位包更新他在 New API 的专属 key：

- **可用模型** = 岗位包勾选的模型 ∩ New API 里启用的渠道模型；交集为空（如岗位包还是旧的演示模型名）时只允许默认模型 `HUB_DEFAULT_MODEL`。下发给 agent 的模型优先用默认模型，不在可用范围内时用第一个可用的。用不在范围内的模型调用，New API 直接返回 403
- **月额度** = 岗位包「每人月模型额度」（人民币，按 `HUB_USD_CNY` 换算）减去本月已用（按调用日志统计），写成 key 的剩余额度，不出现负数；0 表示不限。每次同步都会重算，跨月自动恢复
- 控制台岗位包编辑页的「可用模型」列表来自 New API 的真实渠道

## 控制台

- 岗位包 → 模型与额度：选模型方式、填 GPU 额度
- 用量与成本：上半部分「中枢资源 · 所有 agent」（工具调用、GPU 用时、出图、视频，按人显示 GPU 用量和额度），下半部分「模型 token · 仅中枢模型」

## 计数口径

- 工具调用：审计里结果为「通过」的检索、技能、生成派发；登录、被拒绝的请求不算。调度服务写的完成记录类型为「生成」，不重复计数
- GPU 用时：任务开始到结束的时长，失败的任务也算（GPU 确实被占用了）
- 已有数据库升级时自动加字段，存量岗位包默认「中枢模型、GPU 不限」，行为不变

代码：`console/backend/app/metering.py`（统计）、`generation.py`（额度拦截）、`agent_api.py`（自带模型不发 key）。
