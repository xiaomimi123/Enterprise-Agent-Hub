# 控制台角色与部门

**岗位包**管员工的 agent 能做什么（工具、技能、知识库、额度）；**控制台角色**管人能在控制台里看和改什么。两件事分开配置。

## 三种控制台角色

| 角色 | 来源 | 能看 | 能改 |
|---|---|---|---|
| 系统管理员 | Casdoor 的 `isAdmin` | 全部 | 全部（成员、模型、岗位包、部门与角色、配置） |
| 老板 | 控制台「部门与角色」里的老板名单 | 总览、成员、技能库、知识库、应用、工作看板、审计、生成任务、用量 | 技能：改任何部门的技能直接生效，并审核全公司技能的修改；其余只读 |
| 部门主管 | 「部门与角色」里每个部门的主管名单（一个人可管多个部门） | 自己部门的成员、技能、知识库、工作看板，加上「全公司」的技能和知识库 | 技能：改本部门的直接生效；改「全公司」的要提交审核；不能改别的部门；其余只读 |
| 其他员工 | — | 进不了控制台 | — |

## 默认拒绝

`auth.console_user` 是 `/api` 的全局依赖：管理员全部放行；老板和主管只能用 **GET** 且路径在白名单里（`auth._MANAGER_READ` / `_BOSS_READ`），其余一律 403。成员、模型、部门与角色等接口还显式要求管理员（`auth.current_user`）。**新增接口默认只有管理员能用**，要给老板 / 主管开放必须显式加进白名单，并在处理函数里按 `user["depts"]` 过滤数据。

- 主管看数据时按 `user["depts"]` 过滤：成员、部门、工作看板只含自己的部门；技能和知识库含自己的部门和「全公司」。
- 管理员和老板的 `depts` 是 `None`，表示不过滤。
- 前端按角色隐藏进不去的菜单，访问没有权限的页面会跳回有权限的第一页。前端只是不显示，真正的限制在服务端。
- 员工的 agent 通过 MCP 用 `team_report` 拉团队汇报：老板和管理员看全公司，主管只看自己的部门（逻辑同一套 `roles.resolve`）。

## 部门

- 部门就是 Casdoor 的分组；控制台「部门与角色」可以新建、改名、删除（只有没成员的部门能删）。新建部门的 id 自动生成，管理员只填中文名。
- 每个部门可以配「默认岗位包」：没有单独分配岗位包的成员按它走。没配置时用 `policy.DEFAULT_ROLE_PACKS` 的内置映射，最后是通用岗位包。
- 数据：`console_roles`（老板 / 主管）、`dept_config`（默认岗位包）。删除成员时同时清掉他的角色。

## 已知限制

- 知识库的分类维度（内容类型）、负责人与复核日期，以及 agent 提交改进建议还没做（下面的分期）。
- 原来用于限制 `team_report` 的岗位包工具 `report.view` 已去掉，改为按角色。

## 分期

1. ✅ 部门与角色（本页）
2. ✅ 技能编辑、版本与回滚（[skills.md](skills.md)）
3. ✅ 知识库文档的查看、编辑、版本与审核（[knowledge.md](knowledge.md)）；分类（内容类型）、负责人与复核日期待做
4. agent 提交技能 / 知识库改进建议，主管审核采纳
