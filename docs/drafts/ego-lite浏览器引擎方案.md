# ego lite 浏览器引擎方案（草稿，原型已验证）

> 写于 2026-10-28。背景：用户希望员工不用再装 WorkBuddy 桌面版，由 CodeBuddy 通过 **ego lite** 浏览器读小红书（只读）。结论：**可行，原型在本机验证通过**；是否替代 WorkBuddy 路线，由用户在真实使用中比较「便捷、错误率」后决定。

## 1. ego lite 是什么（已核实）

- 开源（MIT），仓库 `citrolabs/ego-lite`，有 Windows x64 / macOS 安装包；供 AI agent 用的浏览器，每个 agent 有独立的任务空间（Space），沿用用户浏览器的登录态，不抢用户的标签页。
- **不是 MCP**，而是命令行 `ego-browser` 加技能说明：`ego-browser nodejs` 执行一段 JavaScript（浏览器 API：`goto`、`snapshot`、`click`、`evaluate`、`mouse.wheel` 等）。需要人操作时用 `handOff()` 交还，用户说继续后才 `takeOverTaskSpace` 收回。
- 安装：Windows 没有安装脚本，用户下载 exe、运行、做首次设置（可选导入 Chrome 数据），命令才加入 PATH。

## 2. 对我们设计的影响

1. **不能把 agent 写的脚本交给它**（任意代码、能访问文件系统）→ 做固定脚本的只读封装，见 [../../tools/ego-reader/README.md](../../tools/ego-reader/README.md)。
2. **它没有只读档**（设计上就能点击、填表、登录）→ 只读由封装保证，不是靠提示词。
3. **登录、扫码、验证码一律本人操作**，用 `handOff()`；封装遇到用户接管返回 `user_has_control`，不夺回。

## 4. 与 WorkBuddy 路线对比

| | WorkBuddy 插件 | ego lite（原型） |
|---|---|---|
| 员工多装的软件 | WorkBuddy 桌面 + Edge 扩展 | ego lite 一个应用（手动安装 + 首次设置） |
| 控制方式 | MCP，CodeBuddy 直接可用，有只读档 | 命令行 + JS，需要我们的只读封装 |
| 读取方式 | 让模型看页面 | 固定脚本直接取已渲染的数据，快、稳 |
| 维护 | 小红书选择器改版要跟 | 同样要跟；另外要跟 ego lite 接口（版本更新快） |

## 5. 规则措辞（已更新到 CLAUDE.md）

- **允许**：阅读本来就需要的真实操作 —— 点开卡片、鼠标滚轮滚动；固定距离、固定间隔。
- **不做**：随机停顿、鼠标轨迹抖动、模拟走神、按「像真人」拉长间隔等**反检测伪装**。它们的唯一目的是让平台更难识别自动化，也不能保证不触发风控。
- 读取量由服务端节奏限制（总开关、冷静期、每日上限、间隔）控制；仍然不向员工承诺不会触发平台风控。
