# 工作成果与进度（看板 + 老板日报）

老板要看的是「各岗位、各成员做成了什么、进度如何」，不是调用了多少次工具。这一层把两类数据合在一起：

| 类型 | 来源 | 回答什么 |
|---|---|---|
| **成果**（主指标） | 员工的 agent 调用 `report_work` 上报：标题、类型、状态、进度、产物链接 | 做成了什么、卡在哪 |
| **活动**（参考） | 自动统计：审计事件、GPU 任务（出图 / 视频数、调用数、活跃天数、期间无活动的人） | 在不在做 |

调用数、token 不能当绩效（可以被刷）。看板主指标是成果。数据只存标题 / 类型 / 状态 / 链接 / 一句话说明，**不存提示词和正文**。

## 员工侧：report_work / my_work（MCP）

- `report_work(title, kind, status, progress, link, note, item_id)`：状态为 进行中 / 待审核 / 已完成 / 受阻；已完成自动记 100%；链接只允许 http(s)。继续更新同一项带上次返回的 `item_id`，**只能改自己的**。
- `my_work(days)`：看自己上报过的。
- 中枢的 MCP 说明里已写明什么时候上报（完成有交付物的工作、进度变化、待审核、受阻），所以 agent 会自己调用；每次上报也写一条审计（`work.report`）。

## 老板侧

- **控制台「工作看板」**（监管 → 工作看板）：今天 / 近 7 天 / 近 30 天；顶部 KPI；**按岗位** / **按个人** 切换；成果清单（状态、负责人、产物链接）。接口 `GET /api/work/report?days=&person=`。
- **老板的 agent 接中枢 MCP**：调用 `team_report(days, person)`，返回按岗位 / 成员的汇总、成果清单、受阻项、期间无活动的人，以及 `digest`（事实摘要）。老板让 agent「每天 18 点发日报」即可——定时由老板那个 agent 自己的定时任务触发（如 WorkBuddy 的定时任务），中枢不主动推送、也不在服务端调用模型写日报。
- 权限：岗位包里开放工具 **`report.view`（查看团队工作汇报）** 才能用 `team_report`，外部智能体入口一律不行。给老板 / 主管的岗位包在控制台「岗位包」页勾上它。已有的岗位包不会自动获得。

## 口径

- 「今天」= 今天 0 点起；N 天 = 含今天往前数 N 个自然日。
- 成果按「最后更新时间」落在统计区间内计入；同一项更新为已完成后算一项。
- 出图 / 视频只数已成功的 GPU 任务；岗位按成员的岗位包分配（未分配则按部门默认岗位包）。

## 已知限制

- 成果依赖 agent 上报；没上报的工作看不到。看板在没有任何上报时会提示。
- 工作台等应用**还没有自动上报**（现在靠员工的 agent 按 MCP 说明上报）。下一步：应用把关键产出写到本机 outbox，由接入器转发（见接入指南）。
- 还没有「目标 / 任务指派」，所以没有完成率；等看板用起来、确定口径后再做。
- 看板里「期间无活动」只在控制台列出成员时完整；`team_report` 只看有记录的人。
