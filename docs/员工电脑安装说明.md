# 员工电脑安装说明

适用：Windows 10 1809 / Windows 11（64 位）。装完后你可以在桌面双击打开小红书运营工作台，AI 助手自动连上公司的企业智能体中枢。

**不用下载安装包**：只需要在你自己的电脑上运行一行命令，需要的东西都会从中枢下载。大约 5–10 分钟。

## 装之前

1. **连上公司网络**（办公室网络或 VPN）。用浏览器打开 `http://192.168.0.41:8088`，能看到登录页，说明网络没问题。
2. **准备好账号**：管理员给你的中枢账号和初始密码。
3. **关掉 WorkBuddy、CodeBuddy 等 AI 助手**。命令要由你自己运行，让它们代跑会被安全限制拦住。
4. 不需要管理员权限，不需要先装 Node、Python。

## 安装步骤

**第 1 步：打开命令框。** 按键盘 `Win + R`，会弹出一个小窗口。

**第 2 步：粘贴命令。** 复制下面这一整行，粘贴进去，回车：

```
powershell -NoExit -ExecutionPolicy Bypass -c "irm http://192.168.0.41:8088/api/agent/install.ps1 | iex"
```

会弹出一个蓝色（PowerShell）窗口开始工作，**不要关**。

**第 3 步：看自检结果。** 窗口先逐项检查你的电脑，每项显示 `[PASS]`（通过）、`[WARN]`（提醒，不影响安装）或 `[FAIL]`（有问题，必须先处理）。

- 全部通过或只有 WARN：继续自动安装。
- 出现 FAIL：窗口会写明原因，**什么都不会装**。按下面「常见问题」处理后，重新从第 1 步开始。

**第 4 步：等待安装。** 窗口会显示正在下载运行环境（约 90 MB，来自公司中枢，不需要访问外网）。

**第 5 步：登录。** 会自动打开浏览器登录页：

1. 输入账号和初始密码。
2. 第一次登录要求修改密码，改好后继续。
3. 浏览器提示登录成功后，回到蓝色窗口。**登录页只开一个**，放太久（超过 10 分钟）会失效，需要重新运行命令。

**第 6 步：完成。** 窗口提示完成后，桌面和开始菜单会出现岗位对应的应用图标（例如「小红书运营工作台」）。

## 是否安装 CodeBuddy CLI

安装过程中会问：`Install CodeBuddy CLI now? [y/N]`。

- 只使用工作台里的文案、出图、知识库等功能：可以选 `N`。
- 要使用**自动采集和分析**：选 `y`。这一步默认走国内镜像（npmmirror），不需要外网，几秒钟装完；镜像不通会自动退回官方源。装好后还要在**你自己的**终端（Win+R 输入 `cmd`）里运行 `codebuddy`，输入 `/login`，用自己的 CodeBuddy 账号登录一次。

## 怎么用

- 双击桌面上的应用图标打开。**不要通过 AI 助手去打开**，用图标打开的程序在关闭助手后仍然保持运行。
- 想升级时，**重新运行第 2 步的命令**即可，已装好的部分会跳过。

## 以前装过的电脑怎么升级

**不需要先卸载或清理**，重新按「安装步骤」运行同一条命令即可，它能识别已经装好的部分：

- 运行环境（Node、uv、Python）按版本号比对，只在版本不同时才更新；以前装在 Node 目录里的 CodeBuddy 会保留，不用重装。
- 小红书运营工作台不用管，下次打开自动更新。
- 桌面和开始菜单的快捷方式会重建，并补上应用图标。
- 工作台里的数据、CodeBuddy 的登录都不受影响；会再走一次浏览器登录（用同一个账号）。
- 升级前最好**关掉工作台**（开着也能升级，只是旧窗口要关掉重开才会用上新版）。
- 只有一种情况要手动处理：以前在 agent 的技能目录里留下了工作台的旧副本。安装输出里会提示，把那个文件夹删掉就行（数据不在里面）。
- 重新安装时，请用和上次**同一个安装目录**，不要换位置，否则会装出第二份。

## 常见问题

先看蓝色窗口里的提示，每条 FAIL / WARN 后面括号里有一个错误码，下面按错误码查。

| 提示 | 说明 | 怎么办 |
|---|---|---|
| `PREFLIGHT_HUB_UNREACHABLE` 连不上中枢 | 这台电脑访问不到中枢 | 用浏览器打开 `http://192.168.0.41:8088`；打不开就检查网络 / VPN，确认和中枢在同一网络 |
| `PREFLIGHT_CASDOOR_UNREACHABLE` / `PREFLIGHT_MCP_UNREACHABLE` | 中枢能通，但登录端口（8000）或 MCP 端口（8200）被网络拦了 | 联系 IT 放行这两个端口，或换到和中枢同一网络 |
| `PREFLIGHT_AGENT_SANDBOX` 在 agent 里启动 | 命令被 AI 助手拉起 | 关掉 AI 助手，自己按 Win+R 粘贴命令 |
| `PREFLIGHT_PS_CONSTRAINED` PowerShell 被限制 | 安全软件限制了 PowerShell | 联系 IT 放行，或换一台电脑 |
| `PREFLIGHT_PORT_CALLBACK` 登录回调端口被占用 | 另一个程序占了 27891 端口 | 关掉占用的程序，或重启电脑后重试 |
| `PREFLIGHT_DISK_LOW` 磁盘空间不足 | 安装盘剩余不到 1.5 GB | 清理空间，或联系管理员改安装位置 |
| `PREFLIGHT_PATH_UNSAFE` 安装路径不稳妥 | 用户目录含中文、空格或路径过长，启动器容易出错 | 联系管理员，改用纯英文目录（例如 `C:\HubApps`）安装 |
| `PREFLIGHT_NOT_WRITABLE` 安装目录不可写 | 权限规则或受控文件夹访问拦了写入 | 放行该目录，或联系管理员改安装位置 |
| `PREFLIGHT_CLOCK_SKEW` 电脑时间不准 | 和中枢相差超过 5 分钟，登录可能失败 | 把日期、时间、时区设为自动 |
| `PREFLIGHT_PROXY_DEAD` 系统代理指向未运行的程序 | 设置了本机代理但程序没开 | 关掉系统代理，或先启动那个代理程序 |
| `PREFLIGHT_NO_EDGE` 没有 Edge 浏览器 | 页面采集需要 Edge | 不影响安装；要用采集就安装 Edge 和 WorkBuddy 浏览器扩展 |
| `PREFLIGHT_AV_BLOCK` 杀毒软件拦截过文件 | 杀毒软件拦了安装目录里的文件 | 把 `C:\Users\你的用户名\HubApps` 加入杀毒软件的排除项后重试 |
| 登录页提示"状态校验失败" | 登录页开了多个或放太久 | 关掉所有登录页，重新运行命令，只用新开的那一个 |
| 登录输错 5 次被锁定 | 账号安全保护 | 等 15 分钟，或联系管理员 |
| 登录后 CodeBuddy 仍显示未登录 | 登录凭据和 WorkBuddy 桌面共用存储，偶发读不出 | 关掉 WorkBuddy 和所有 codebuddy 窗口，在自己的 cmd 里运行 `codebuddy` → `/login`；仍不行联系管理员 |
| 提示 `BUNDLE_FAILED` 底座包安装失败 | 从中枢下载运行环境失败或文件校验不通过 | 重新运行命令；仍失败联系管理员（会自动退回联网安装，需要能上外网） |
| 窗口停在 `Downloading` / `Unpacking` 很久 | 正在下载或解压运行环境（约 95 MB，几千个小文件），虚拟机里可能要几十秒到几分钟 | 别关窗口，耐心等。旧版脚本在虚拟机里会因为进度条显得像卡死，重新运行命令即可用上新版 |
| 桌面上的应用图标是空白的 | 快捷方式还没有图标，或 Windows 的图标缓存没刷新 | 重新运行一次安装命令（会下载图标并重建快捷方式）；仍空白就刷新桌面（F5）或重启资源管理器 |
| CodeBuddy 安装失败（`NPM_FAILED`） | 国内镜像和官方源都没连上 | 检查网络 / 代理后重新运行命令，选 `y` 重试；管理员可用环境变量 `HUB_NPM_REGISTRY` 指定公司内部镜像 |

## 遇到问题怎么联系管理员

把下面两样发给管理员，比截图更快：

1. 蓝色窗口里 `[FAIL]` / `[WARN]` 那几行文字，**包括括号里的错误码**。
2. 文件 `%TEMP%\hub-preflight.json`（自检报告，不含密码和令牌）。

自检失败的信息会自动匿名上报到中枢，管理员在控制台「应用健康」页能看到你的电脑卡在哪一步，不需要你解释。

## 管理员备注

- 命令里的地址是中枢的局域网 IP；换网络或 IP 变了，这份说明里的地址和 Docker 里的 `HUB_HOST` 要一起改。
- 底座运行环境在管理员机器上用 `node tools/build-bundle/build.mjs` 构建，说明见 [../tools/build-bundle/README.md](../tools/build-bundle/README.md)；没有底座包时安装会退回联网下载。
- 新机器上线前，建议先在 Windows 沙盒里跑一遍验收：[../tools/clean-room/README.md](../tools/clean-room/README.md)。
- 完整流程（含登录、桌面图标）目前只在沙盒验证到"装底座和依赖"，第一台真实新电脑安装时请留意每一步，并把出错输出发给开发。
