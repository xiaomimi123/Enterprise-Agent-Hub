# 7 知识库

知识库是员工 agent 回答「本公司」问题的依据：产品卖点、品牌口径、违禁词、制度、话术、爆款案例。它由三部分组成：**知识库本身**（名称、归属、密级、类型、负责人）、**文档**（Markdown，带版本）和**检索索引**（RAGFlow 混合检索）。权限始终在中枢判定，检索只是执行层。

## 7.1 知识库元数据与内容分类

知识库本身存在 `kbs` 表里，首次启动时从内置清单导入。除了名称、所属部门、密级、是否开放给外部智能体，还有三项用来治理内容质量的字段：

| 字段 | 含义 |
|---|---|
| 内容类型 | 制度、产品、品牌、案例素材、话术、合规、复盘、其他；列表可按 部门 × 内容类型 × 密级 筛选 |
| 负责人 | 对内容准确性负责的人（用户名） |
| 复核周期 | 默认 90 天，0 表示不需要；负责人、主管、老板、管理员可标记「已复核」重新计时 |

权限和检索代码里到处在读 `content.KB_REGISTRY` / `KB_BY_NAME` 这两个字典。为了不改所有调用处，数据库化采用**原地刷新**：这两个字典对象保持不变，`kbmeta.refresh()` 按数据库更新它们的内容（先加后删，读的线程不会看到缺项），每个进程最多每 30 秒读一次库，走接口修改后立即刷新。没配置数据库（单元测试、演示模式）时保持内置数据。

{{code console/backend/app/kbmeta.py::refresh | console/backend/app/kbmeta.py}}

**谁能改什么**：只有管理员和老板能新建知识库、修改名称、所属部门、**密级和是否开放外部**（这两项直接决定信息会不会外泄；机密库不能开放外部）。部门主管只能改本部门知识库的负责人、内容类型、复核周期和说明。新建后要由管理员在「岗位包」里授权，员工的 agent 才能检索到。

## 7.2 文档、版本与审核

文档（Markdown）存在 `kb_docs` / `kb_doc_versions`，机制与技能库（6 章）一致：

- **同一套权限规则**（`plan_for`）：本部门知识库主管保存即生效，全公司知识库由主管修改需老板或管理员审核，老板和管理员直接生效；新建、修改、删除、回滚都走同一套。
- **每次保存是新版本**；**删除也是一个版本**（文档从检索里去掉，但历史保留，可在「已删除的文档」里回滚找回）；回滚是用旧内容生成新版本。
- 乐观并发（`base_version`）、一篇文档同时只有一份待审核的修改、事务内 `FOR UPDATE`，与技能库相同。
- 文档名 1–60 个字，不含 `\ / : * ? " < > |`，不以点开头；内容不超过 256 KB。
- 首次启动把 `vault/<知识库名>/**/*.md` 导入为第 1 版（同库同名只导入第一篇）。

```sql console/backend/app/db.py — 知识库文档表
CREATE TABLE IF NOT EXISTS kb_docs (
    kb_id TEXT NOT NULL, name TEXT NOT NULL,
    published_version INTEGER NOT NULL DEFAULT 0,
    synced_version    INTEGER NOT NULL DEFAULT 0,   -- 已同步到检索索引的版本
    deleted BOOLEAN NOT NULL DEFAULT false,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    PRIMARY KEY (kb_id, name)
);
CREATE TABLE IF NOT EXISTS kb_doc_versions (
    kb_id TEXT NOT NULL, name TEXT NOT NULL, version INTEGER NOT NULL,
    content TEXT NOT NULL,
    is_delete BOOLEAN NOT NULL DEFAULT false,      -- 这一版是「删除」
    author TEXT, author_name TEXT, note TEXT,
    status TEXT NOT NULL,                          -- published | pending | rejected
    reviewer TEXT, review_note TEXT, reviewed_at TIMESTAMPTZ, created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    PRIMARY KEY (kb_id, name, version),
    FOREIGN KEY (kb_id, name) REFERENCES kb_docs (kb_id, name) ON DELETE CASCADE
);
```

## 7.3 检索流程与权限前置

1. MCP `search_knowledge` 解析 Principal，按岗位包得到允许的知识库集合（4.3 节）。
2. 若指定了库名且不在集合内 → 拒绝并写拦截审计，原因精确到「岗位包没有该库」或「该库未对外开放」。
3. `content.search()` 把允许的知识库映射为 RAGFlow 数据集 ID：**没有同步到 RAGFlow 的库直接跳过，绝不扩大范围**。
4. RAGFlow 返回分块后，再丢弃任何不属于本次允许库的命中（纵深防御），映射为统一结构：知识库、文档、正文、得分。
5. RAGFlow 不可达、超时、返回错误或非 JSON 时，记 warning 并**回退本地二元组关键词检索**，返回结构相同，MCP 调用不中断；本地回退读的是数据库里的已生效版本。

{{code console/backend/app/content.py::search | console/backend/app/content.py}}

嵌入模型是 RAGFlow 自带 TEI 服务运行的 Qwen3-Embedding-0.6B（1024 维，多语言，中文效果好），CPU 推理，不占 GPU；分块用 RAGFlow `naive` 解析器；检索采用向量相似度加关键词相似度的加权混合，兼顾语义召回与专有名词精确匹配。

## 7.4 本地回退算法：字符二元组

回退检索不依赖分词器：把查询和段落都拆成相邻两字的集合（中文天然适用），以查询二元组被段落覆盖的比例为得分，查询原文整体出现时再加 1 分，阈值 0.15 以上返回。召回质量不如向量检索，但零依赖、确定性强，适合作为降级方案。

## 7.5 发布后同步到检索索引

文档发布（保存即生效、审核通过、删除、回滚）后，控制台接口立即把这一篇同步到 RAGFlow：删掉同名旧文档、上传新内容、触发解析；已删除的文档只删旧的。同步失败**不影响文档已经保存**：`kb_docs.synced_version` 与 `published_version` 不一致时，列表里显示「待同步」，可以在控制台点「重试同步」。员工的 agent 因此在管理员保存后几秒内就能检索到新内容（已实测：新增文档同步后被员工 agent 经 RAGFlow 检索命中）。

{{code console/backend/app/kbstore.py::sync_doc | console/backend/app/kbstore.py}}

全量对齐用 `make kb-sync`（`scripts/ragflow_sync.py`）：配置了数据库时以数据库里的已生效版本为准，按「文件名 + 字节数」判断是否变化——没变就跳过，变了先删旧文档再上传新的，数据库里已删除的文档从 RAGFlow 删除。

> **取舍**：按字节数判断变化足以覆盖知识库的实际编辑场景，又不需要在 RAGFlow 侧保存内容哈希。极端情况下「改了内容但字节数恰好相同」会漏同步；单篇发布路径总是删除重传，不受影响。

## 7.6 复核周期与逾期提示

知识库的内容会过时，所以每个库有复核周期。`kbmeta.is_overdue` 判断是否逾期（从未复核过也算逾期），列表里逾期的标红；老板和主管的日报（`team_report`，9 章）会带上逾期清单，主管只看自己部门和全公司的。逾期提醒只在控制台和日报里，不单独推送。

## 7.7 客户端实现细节

- 单例客户端：`from_settings()` 复用同一个 `httpx.Client`（连接池），避免每次检索新建连接。
- 数据集 ID 缓存 60 秒；**只缓存命中，不缓存未命中**，保证新同步的库立刻可见。
- RAGFlow 对不存在的名称做 `name` 过滤时会返回「无权限」而不是空列表，因此列表查询不带名称过滤，全量分页后本地匹配。
- 所有异常（网络、HTTP 4xx/5xx、`code != 0`、非 JSON）都统一转为 `RagflowError`，上层只需处理一种异常即可回退。

## 7.8 接口与审计

| 接口 | 说明 |
|---|---|
| `GET /api/knowledge-bases`、`POST`、`PATCH /{id}`、`POST /{id}/reviewed` | 列表（含类型、负责人、复核状态）/ 新建 / 改属性 / 标记已复核 |
| `GET /api/knowledge-bases/{id}/documents`、`GET …/documents/{name}` | 文档列表（版本、片段数、索引状态）/ 内容与版本历史 |
| `POST …/documents`、`PUT …/documents/{name}`、`DELETE …/documents/{name}` | 新建 / 保存 / 删除 |
| `POST …/documents/{name}/rollback`、`GET …/deleted`、`POST …/sync` | 回滚（含找回）/ 已删除的文档 / 重试同步 |
| `GET /api/kb-reviews`、`POST /api/kb-reviews/{kb}/{name}/{version}` | 待审核列表 / 通过或驳回 |

审计：`kb.create` / `kb.edit` / `kb.delete` / `kb.rollback` / `kb.review` / `kb.create_base` / `kb.settings` / `kb.reviewed`，只记知识库、文档名、版本和说明，不记内容。
