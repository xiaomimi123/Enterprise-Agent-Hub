# 8 改进建议

员工的 agent 在干活时最先发现技能写错了、过时了、缺步骤，或者知识库里某条不准确。改进建议这一层让它把发现**提成建议**，由人审核后才生效，形成「一线发现问题 → 主管决定修改」的闭环，也是技能和知识库「自我进化」的安全做法（ADR-8）。

## 8.1 原则

- **agent 只能提建议，不能直接改。** 采纳后才通过现有的版本流程（6、7 章）产生新版本，可回滚。
- **建议是不可信输入。** 只给人看（差异对比），从不自动执行或发布；技能建议必须是合规的 `SKILL.md`，大小有上限。
- **谁来审跟着内容走**：本部门内容的建议由该部门主管处理；全公司内容只有老板和管理员；老板和管理员可以处理所有的（与技能库 / 知识库的审核规则一致）。
- **有限额、防刷屏**：每人每天最多 10 条；同一个人对同一目标同时只能有一条待处理的（数据库部分唯一索引保证）。
- **只在有把握时提**：中枢的 MCP 说明和工具描述都要求 agent 不要每次任务都提。

## 8.2 员工 agent 侧：两个 MCP 工具

| 工具 | 说明 |
|---|---|
| `propose_improvement(kind, target, summary, rationale, proposed_content, knowledge_base, evidence)` | `kind`：`skill`（改技能，target 填技能 id）、`doc`（改已有文档，target 填文档名 + `knowledge_base` 填库名）、`new_doc`（新增文档，必须带完整内容）。`proposed_content` 最好带上修改后的完整内容，审核人才能直接看到差异 |
| `my_proposals(days)` | 看自己提交过的建议和结果（待处理 / 已采纳 / 已驳回及原因），让 agent 知道反馈 |

提交前，工具实现会先检查 agent 是否有权读这个技能或知识库（岗位包），再调用 `proposals.create` 校验目标存在、内容合规、限额和去重。

## 8.3 审核侧：控制台「改进建议」页

- 列表按待处理 / 已处理；详情显示原因、依据，以及建议内容和**当前内容**的差异。
- **采纳并生效**：用建议的内容生成新版本并发布（知识库文档同步到 RAGFlow）。**修改后采纳**：先在编辑框里改，再采纳。没带新内容的建议，审核人在编辑框里写好再采纳。
- **驳回**：必须写原因，会反馈给提出建议的人（`my_proposals`）。
- **旧版本提醒**：建议提出后目标又被改过，会标记「基于旧版本」，采纳前要勾选「已对照最新内容确认」，否则服务端拒绝。
- **并发安全**：采纳先用 `UPDATE … WHERE status = 'open'` 占住这条建议，再应用修改；应用失败会恢复成待处理，让审核人修改后重试，不会出现「建议被吞掉」。

## 8.4 反馈与可见性

- 采纳后新版本的作者是审核人，说明里写「采纳 xxx 的建议：…」；**提出人的这次采纳记成一项成果**（类型「改进建议」），出现在工作看板里，让好建议被看见。
- 老板和主管的 `team_report` 日报带「待处理的改进建议 N 条」。
- 审计：`proposal.create`（agent 提交）、`proposal.accept` / `proposal.reject`（控制台处理）。

## 8.5 接口与数据

| 接口 | 说明 |
|---|---|
| `GET /api/proposals?status=open\|closed` | 当前角色能处理的建议（主管只含自己部门） |
| `GET /api/proposals/{id}` | 详情：原因、依据、建议内容、当前内容、是否基于旧版本 |
| `POST /api/proposals/{id}/accept` | 采纳（`content` 可选、`note`、`confirm_stale`） |
| `POST /api/proposals/{id}/reject` | 驳回（`note` 必填） |

建议存在 `proposals` 表（类型、目标、所属部门、提出人、说明、依据、建议内容、基于的版本、状态、审核人和意见）。

## 8.6 已验证与限制

端到端测试 `scripts/e2e_proposals.py` 覆盖 38 项：真实登录（员工 agent 走 PKCE）+ 真实 MCP + 真实控制台接口；并用真实的 CodeBuddy CLI 验证过：agent 读取中枢技能、遇到用户口头声称的变更时不照单全收（对照知识库、技能、手册三处口径后要求用户确认），确认后提交了带完整内容的建议且没有改技能原文。

**限制**：目前没有「让模型根据多条建议自动起草改写稿」，只有人工审核；agent 要不要提、提得对不对取决于它自己的判断，中枢只负责收集、审核和反馈；建议只能针对已有的技能、知识库文档和新增文档，新建技能和改知识库属性不在范围内。
