# 15 控制台前端

技术栈：React 19 + TypeScript（严格模式）+ Vite + Ant Design 6 + ECharts + Lucide 图标；Markdown 渲染用 react-markdown（默认不渲染原始 HTML）。数据访问集中在 `api.ts`（类型与请求），页面通过 `useRequest` hook 获取数据并支持 `reload`。

## 15.1 按角色显示菜单

`session.user.role`（管理员 / 老板 / 部门主管，4.5 节）决定菜单。每个菜单项声明哪些角色能看到；访问没有权限的路径会跳回有权限的第一页。**这只是不显示进不去的菜单，真正的限制在服务端**（默认拒绝）。

| 菜单 | 管理员 | 老板 | 部门主管 |
|---|---|---|---|
| 总览、应用、审计日志、生成任务、用量与成本 | ✓ | ✓ | — |
| 成员与组织 | 可编辑 | 只读 | 只读（本部门） |
| 部门与角色、岗位包、模型、接入方式 | ✓ | — | — |
| 技能库、知识库、改进建议、工作看板 | ✓ | ✓ | ✓（本部门 + 全公司） |

## 15.3 内容编辑与差异对比

技能和知识库的编辑器是普通的多行文本框加「修改说明」，重点在流程而不是编辑器本身：

- **直接生效还是提交审核**由服务端告诉前端（`history` 接口返回 `mode`）：按钮文字随之变成「保存并生效」或「提交审核」；
- **差异对比**（`DiffView`）用逐行最长公共子序列算出新增 / 删除，只保留改动前后各 2 行，其余折叠；版本历史、待审核列表、改进建议都用它，审核人看到的永远是和**当前内容**的差异；
- 保存冲突（409）、格式不合规（400）、同步失败等都给出可执行的提示，而不是通用错误。

## 15.4 双轨主题系统

亮色「作业本」与暗色「黑板」两套主题需要同时作用于三类渲染：CSS、Ant Design 组件、ECharts Canvas。Canvas 读不到 CSS 变量，因此采用**双轨同源**设计：

- **CSS 轨**：`index.css` 在 `:root` 与 `:root[data-theme="dark"]` 定义同名令牌（`--bg`、`--ink`、`--accent`、`--green` 等），所有样式只引用令牌。
- **JS 轨**：`theme.tsx` 的 `PALETTE` 保存同一套颜色，供 Ant Design（`ConfigProvider` 的 token 与 `darkAlgorithm`）和 ECharts 使用。
- **切换**：`ThemeProvider` 设置 `document.documentElement.dataset.theme` 与 `color-scheme`；首次按 `prefers-color-scheme`，之后记入 localStorage（读写包在 try/catch 中，隐私模式下降级）。
- **ECharts**：为亮 / 暗各注册一份主题，`EChart` 组件在主题变化时 dispose 并按新主题重建实例，再回放最近一次 option。
- **SVG**：拓扑图与迷你折线直接使用调色板值，或用 `style` 写 CSS 变量（SVG 展示属性不可靠地支持 `var()`）。
- **浅色底**：`color-mix(in srgb, 色值 16%, transparent)` 生成在亮、暗两种背景下都不刺眼的着色底。
