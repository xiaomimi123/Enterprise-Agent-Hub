# 16 数据模型

中枢自研服务使用 PostgreSQL 的 `hub` 库。表结构在服务启动时以 `CREATE TABLE IF NOT EXISTS` 创建，后续新增字段用 `ALTER TABLE … ADD COLUMN IF NOT EXISTS`，实现**无迁移工具的前向兼容升级**：存量库启动即补齐字段，默认值保证旧数据行为不变。技能、知识库文档和知识库元数据在首次启动时从磁盘 / 内置清单导入，之后以数据库为准。

## 16.1 表清单

| 表 | 主键 | 主要字段 | 用途 |
|---|---|---|---|
| `role_packs` | id | skills / knowledge_bases / tools / models / apps（JSONB）、monthly_quota、model_mode、gpu_quota_minutes、max_action_level、external_access | 岗位包定义 |
| `role_assignments` | (org, user_name) | role_pack_id | 按人指派岗位包 |
| `dept_config` | (org, dept_id) | role_pack_id | 部门默认岗位包（优先于内置映射） |
| `console_roles` | (org, user_name, role, dept_id) | role（boss / manager）、dept_id | 老板 / 部门主管 |
| `audit_events` | id（自增） | trace_id、ts、user_name、channel、kind、tool、detail、result、tokens、model、cost、summary | 审计事件，索引 trace_id 与 ts |
| `gpu_nodes` / `gpu_tasks` | id | 节点 url、在线、显存；任务 workflow、params、status、node_id、images、attempts、时间戳 | GPU 节点与任务队列（索引 status, created_at） |

## 16.2 几个值得一提的设计

- **版本表而不是覆盖**：技能和知识库文档永远只追加版本，`published_version` 指向已生效的那一版；回滚、删除都是追加新版本。要查「谁在什么时候改过什么」只看版本表。
- **部分唯一索引做幂等和防刷**：`work_items` 的 `(org, user_name, source, ext_key) WHERE ext_key <> ''` 让应用重复上报变成更新；`proposals` 的 `(proposer, kind, kb_id, target) WHERE status = 'open'` 保证同一个人对同一目标同时只有一条待处理建议。
- **自动提交连接与显式事务**：`db.connect()` 是自动提交的，凡是要改多张表或需要行锁的写操作（技能 / 文档的提交、审核、导入）都包在显式事务里；读操作不需要。
- **JSONB 存岗位包的集合字段**（技能、知识库、工具、模型、应用 id 列表），避免为一对多关系建关联表；代价是不能用外键保证引用有效，由控制台编辑时校验。

```sql console/backend/app/db.py — 改进建议表与幂等索引
CREATE TABLE IF NOT EXISTS proposals (
    id               BIGSERIAL PRIMARY KEY,
    kind             TEXT NOT NULL,                -- skill | doc | new_doc
    kb_id            TEXT NOT NULL DEFAULT '',     -- 知识库 id（kind 为 doc / new_doc 时）
    target           TEXT NOT NULL,                -- 技能 id 或文档名
    dept_id          TEXT NOT NULL,                -- 目标所属部门（all = 全公司），决定谁来审核
    proposer         TEXT NOT NULL,
    summary          TEXT NOT NULL,
    proposed_content TEXT,
    base_version     INTEGER NOT NULL DEFAULT 0,   -- 提出建议时目标的版本
    status           TEXT NOT NULL DEFAULT 'open', -- open | accepted | rejected
    ...
);
CREATE UNIQUE INDEX IF NOT EXISTS proposals_one_open ON proposals (proposer, kind, kb_id, target) WHERE status = 'open';
```

## 16.3 备份

技能、知识库文档及其全部版本、岗位包、角色、审计、建议、成果都在 `hub` 库里，**备份必须包含 PostgreSQL**（`pg_dump hub`、`casdoor`、`newapi`）。仓库里的 `skills/`、`vault/` 只是初始数据，改这些目录里的文件不再生效。另需备份 `hub/.env`、`hub/data/outputs/`（生成的图片和视频）和 RAGFlow 数据卷（索引可由 `make kb-sync` 从数据库重建）。
