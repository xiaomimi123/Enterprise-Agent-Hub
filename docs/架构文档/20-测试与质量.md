# 20 测试与质量

后端有 **350 个自动化测试**（pytest，30 个测试文件，约 3 秒跑完），前端有 TypeScript 严格类型检查和 oxlint，小红书运营工作台另有 359 项测试。测试分层如下：

| 层次 | 方法 | 示例 |
|---|---|---|
| 纯函数 | 直接断言输入输出 | `plan_key`、`video_frames`、`hub_usage`、`member_agent`、`attach_model_calls`、`build_report`、`plan_for`、`kbmeta.due_in_days`、`_clean`（各类输入校验） |
| 权限矩阵 | 参数化测试遍历「角色 × 方法 × 路径」 | 主管 / 老板的白名单：该放行的放行，其余一律拒绝（默认拒绝）；谁能改谁的技能和知识库、谁能处理哪条建议 |
| 外部依赖 | `httpx.MockTransport` 或注入假对象 | RAGFlow 客户端、New API、ComfyUI、接入器的 `flush_outbox`（假的上传函数）、数据库函数 monkeypatch |
| 接口 | FastAPI `TestClient`（演示模式） | 安装脚本、心跳、生成接口的 202 / 400 / 403 / 429；演示模式下看板为空而不是报错 |
| 回归 | 针对真实踩过的坑 | `CasdoorProvider` 里重复定义的 `kb_documents` 曾让后一个覆盖前一个，导致文档详情 404，现用测试断言它只有一个且读数据库 |
| 端到端 | 真实登录 + 真实接口 / MCP，在本机 Docker 全栈上跑 | `scripts/e2e_proposals.py`（38 项）；各功能上线时用真实的主管 / 老板 / 员工账号逐项验证后清理测试数据 |
| 真实 agent | 真实的命令行 agent 按工作台的提示词执行 | CodeBuddy CLI 2.171.0：读手册、读中枢技能、遇到未经确认的变更要求确认、确认后提交建议 |

## 20.1 测试方法上的两条教训

- **只调内部函数会漏掉接口层的问题。** 验证一个功能时要走「真实登录 → 真实接口或 MCP」这条路径，而不是只调用内部函数；`e2e_proposals.py` 就是这个原则的样板，里面有控制台登录（授权码）和员工 agent 登录（PKCE）两种无界面登录的写法。
- **测试数据要清理，且只还原自己改过的版本。** 端到端测试会创建账号、角色、技能和文档版本，结束时必须删除，并且只把「这次测试改过的版本」恢复到测试前的快照，不能误删用户真实的编辑。

## 20.2 工作台与文档

- 工作台的自动化测试用 `node:test`，覆盖中枢对接的三个模块（环境变量契约、能力预检、成果上报）和提示词指引；本机没装 ffmpeg 时参考视频相关的 2 项会失败，与功能无关，打包时先单独跑其余测试再 `--skip-tests`。
- 本文档由 `tools/docs` 从 `docs/架构文档/*.md` 生成 Word 和 PDF，代码片段在构建时从源码摘取（引用的函数不存在会直接报错），所以代码与文档不会悄悄脱节；文档里的相对链接另有检查脚本。
