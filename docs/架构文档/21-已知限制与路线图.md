# 21 已知限制与路线图

## 21.1 已知限制

- **模型调用归属**：同一员工并行会话且都走基础 key 时，按时间窗归属可能归错（12.2 节）。
- **检索结果不带章节标题**：RAGFlow 按分块返回；知识库文档同步按单篇删除重传，全量对齐按「名称 + 字节数」判断，极少数「改内容不改大小」的编辑在全量对齐时会漏。
- **内容只在数据库里**：技能和知识库不再用 Obsidian / git 维护，备份必须包含数据库；知识库只支持 Markdown，PDF / Word / Excel 上传还没做。
- **知识库不能删除**（只能改属性）；逾期提醒只在控制台和日报里，不单独推送。
- **改进建议**：没有「让模型根据多条建议起草改写稿」，只有人工审核；建议只覆盖已有的技能、文档和新增文档。
- **工作成果依赖上报**：没上报的工作看不到；没有目标 / 任务指派，所以没有完成率。
- **应用分发**：接入器写死用 `node` 启动应用，`requires` 目前只有 `codebuddy` / `browser` 两种能力；里面还有工作台的特例；应用自带的模型密钥（生图、视频）没有统一到中枢；工作台自己的知识库和中枢知识库是两套。
- **真实 agent 的覆盖**：真实验证的是 CodeBuddy CLI；工作台里 Claude Code 调用中枢工具、其他桌面 agent 是否会主动提改进建议，还没有真实验证。
- **浏览器界面的验证**：新增的控制台页面（部门与角色、技能和知识库编辑、改进建议、知识库设置）由用户在浏览器里试用；自动化验证覆盖到接口和权限层。
- **传输安全**：目前只有局域网 HTTP，没有 HTTPS。
- **在线状态只有当前值**，没有历史在线趋势。

## 21.2 路线图

| 优先级 | 事项                                                           | 依赖             |
| --- | ------------------------------------------------------------ | -------------- |
| P0  | 同事电脑试点一键接入，验证局域网访问、真人浏览器登录，以及主管 / 老板日常使用控制台的流程               | 一台同事电脑、真实的主管账号 |
| P0  | 用真实使用反馈调整：业务技能的内容（主管补充）、知识库的分类与复核周期、改进建议的提法                  | 试点使用           |
| P1  | 让模型根据多条改进建议自动起草改写稿（仍由人审核发布）                                  | 模型调用额度         |
| P1  | 工作成果加上目标与任务指派，看板显示完成率                                        | 老板确定口径         |
| P1  | 知识库支持 PDF / Word / Excel 上传与解析                               | RAGFlow 解析能力   |
| P1  | New API 透传追踪 ID，替代时间窗归属                                      | 无              |
| P1  | HTTPS 与安全 cookie，支持对外访问；云服务器部署（香港 + 隧道连本地 GPU）               | 域名与证书          |
| P2  | 应用对接契约去掉工作台特例：`app.json` 声明运行时、启动检测、说明文案；第二个应用接入验证模式         | 第二个应用          |
| P2  | 应用自带模型密钥统一到中枢（走 `generate_image` / `generate_video`），额度和审计集中 | 工作台新增「中枢通道」    |
| P2  | 员工端安装包（内置 uv、托盘、本机动作确认弹窗）                                    | 无              |
| P2  | 多 GPU 节点按工作流能力派发；视频粗剪工作流；在线与用量历史趋势                           | 第二台 GPU 机器     |

已放弃的方案：钉钉扫码登录与通讯录同步——身份改为直接使用 Casdoor 自建账号（成员由管理员在控制台创建、批量导入、停用），钉钉保留为日后可选的第二登录方式。
