# 测试流程：CodeBuddy CLI 通过 WorkBuddy 浏览器插件操作 Edge（小红书运营工作台 0.8.5 / 接入器 0.5.4）

> 这份文件发给**新 Windows 电脑上的 WorkBuddy**，由它按步骤执行并写测试报告，电脑前的同事配合完成需要本人操作的步骤。
> 目标是验证：工作台里需要浏览器的功能，能由 CodeBuddy CLI 通过 WorkBuddy 的 Edge 插件，在**用户自己的 Edge** 里完成。
>
> 0.8.5 起网页是主界面：CodeBuddy 的登录检查、浏览器方式、权限档都在网页「连接与设置」里点选，第 3 步不再需要在终端里跑命令。
> 第一轮测试（10-23，工作台 0.8.3）的结论和这次的变化：核心链路已通过；测试 B 的预期改了（只读档允许打开网址，见下）；测试 D 当时因为日常 Edge 没登录小红书被挡住，这次先在第 3.5 步登录。

---

## 给 WorkBuddy 的规则（必须遵守）

1. **只读**：整个测试中，不点赞、不评论、不关注、不私信、不发布、不修改任何账号资料。
2. **登录、扫码、验证码、密码一律由同事本人操作**。你不输入任何账号密码，不替人扫码；遇到验证码或风险提示，立即停下来请同事处理。
3. **你的沙箱可能拦截命令**（例如 `iex`、`Start-Process`）。被拦时不要换写法绕过：把命令原样告诉同事，请他在自己的 PowerShell 里运行（按 Win+R，输入 `powershell`，回车），再把输出贴回给你。
4. **工作台不要由你启动**。由你拉起的程序会在你退出时被一起结束，所以请同事双击桌面上的「小红书运营工作台」打开它。
5. 每一步都把**实际看到的输出原文**记进报告，不要只写「成功」。和预期不一致时，照实记下，继续做下一步。
6. 不要修改工作台或接入器的任何文件。发现问题就记下来，不要自己打补丁。

## 第 0 步：前提检查

请同事确认，或由你执行后记录结果：

| 检查项 | 怎么查 | 预期 |
|---|---|---|
| 能连上中枢 | 浏览器打开 `http://192.168.0.41:8088` | 出现登录页 |
| Edge 插件 | WorkBuddy「设置 > 智能体 > 浏览器操控」 | 「让 WorkBuddy 控制浏览器」已开，Edge 扩展「已安装」 |
| CodeBuddy CLI 已登录 | 同事在**自己的** PowerShell 里运行：`echo 只回复 PONG \| codebuddy -p` | 回复 `PONG`（不能是 `Authentication required`） |
| 浏览器插件程序存在 | 查看文件 `%USERPROFILE%\.workbuddy\plugins\cache\workbuddy-browser-use\browser-use\` 下有版本目录，里面 `bin\browser-mcp.exe` 存在 | 存在 |
| 中枢账号 | 同事有自己的中枢账号和密码（管理员在控制台建的） | 有 |

> CodeBuddy 必须在同事自己的终端里登录：运行 `codebuddy`，输入 `/login`，登录后输入 `/exit`。**不要在 WorkBuddy 的终端里登录**，那样登录会存到 WorkBuddy 自己的目录，CodeBuddy CLI 用不上。

## 第 1 步：接入中枢（同事操作）

> **已经接入过的电脑也要做这一步**：它会把接入器升级到 0.5.4，并在桌面放上中枢的「小红书运营工作台」启动器（启动器不写版本号，总是向中枢要最新版）。之前 agent 自己做的启动器（比如 `.vbs`、`start-workbench-clean.mjs`）请删掉，以免打开旧版本。

1. 同事按 Win+R，粘贴下面这一行，回车：

   ```
   powershell -NoExit -ExecutionPolicy Bypass -c "irm http://192.168.0.41:8088/api/agent/install.ps1 | iex"
   ```

2. 浏览器弹出登录页时，同事用自己的中枢账号登录（首次登录要改密码），回到命令窗口等它跑完。
3. 你记录命令窗口最后 15 行输出。

**预期：**
- 输出里有「App root: C:\Users\…\HubApps」，以及 `[1/5]` 到 `[5/5]` 五步。
- 有「WorkBuddy 目录权限」「CodeBuddy CLI 目录权限」两行，内容是「已把 … 登记」或「已登记」。
- 有「应用启动器」一行，写着「以后双击桌面上的「小红书运营工作台」打开应用」。
- 桌面上出现「小红书运营工作台」图标。
- 最后提示完全退出并重新打开 WorkBuddy。

4. 请同事**完全退出并重新打开 WorkBuddy**（托盘图标也要退出）。

---

## 第 2 步：打开工作台（同事操作）

1. 同事**双击桌面上的「小红书运营工作台」**。
2. 浏览器打开工作台网页（地址类似 `http://127.0.0.1:17890/...`）。

**预期：** 网页能打开；「连接与设置」页显示版本 **0.8.5**；「企业中枢」一行显示「已接入」。

记录：页面显示的版本号、连接与设置页的截图或文字。

---

## 第 3 步：在网页里设置 CodeBuddy 和浏览器（同事操作，全程不用终端）

打开工作台网页的「连接与设置」，最上面是「执行 Agent 与浏览器」卡片。

1. **CodeBuddy 状态**：打开页面后它会自动检查一次（最长约 2 分钟）。
   - 显示「已登录，可以使用」：通过。
   - 显示「还没登录」：点「去登录」，**桌面上会弹出一个终端窗口**运行 codebuddy；第一次会问是否信任文件夹，选第 1 项回车；再输入 `/login`，在浏览器里登录 CodeBuddy 账号，完成后输入 `/exit`；回到网页点「重新检查」，应变成「已登录，可以使用」。
   - **预期**：连接方式已经自动是 CodeBuddy（不需要选 agent，也没有把 WorkBuddy 设成值守者）。
2. **浏览器方式**：在「我自己的 Edge（WorkBuddy 插件）」那一行点「用这个」。
   - 会先跑一次连接测试（最长约 3 分钟），通过后这一行出现「当前」，提示「已切换到你自己的 Edge」。
   - 如果显示「没有找到 WorkBuddy 浏览器插件」，按提示在 WorkBuddy 里打开浏览器操控、安装 Edge 扩展后再点。
3. **权限档**：确认显示「权限档：只读档」。点一次「切到测试档」，应弹出确认框，**点取消**（这次不测测试档），权限档仍是只读档。

记录：三处显示的原文；「去登录」是否弹出了终端窗口；切换浏览器方式用了多久、有没有报错。

> 网页设置失败时的后备做法（在同事自己的 PowerShell 里运行，把输出贴回来）：
> `node "<WB>" bridge-test --agent codebuddy`，然后 `node "<WB>" browser-setup --engine workbuddy --yes`。
> `<WB>` 是 `%USERPROFILE%\HubApps\apps\xhs-workbench\0.8.5\xhs-workbench\scripts\workbench.mjs`（找不到就在 `%USERPROFILE%\HubApps\apps\xhs-workbench\` 或 `%USERPROFILE%\.hub-agent\apps\xhs-workbench\` 下找 0.8.5 目录；`node` 找不到时用 `%USERPROFILE%\HubApps\runtime\node\node.exe`）。

## 第 3.5 步：在自己的 Edge 里登录小红书（同事操作）

插件方式操作的是同事**自己日常用的 Edge**，用的是这个浏览器里的登录，和工作台自己的浏览器（第 6 步）是两套。

1. 同事在自己的 Edge 里打开 `https://www.xiaohongshu.com`，用小红书 App 扫码登录**要用来运营的那个账号**。
2. 如果页面提示「设备登录超限」：先在小红书 App 里（设置 → 账号与安全 → 登录设备管理，或类似入口）退掉一台不用的设备，再扫码。
3. 登录后右上角能看到头像和昵称。

记录：登录的是哪个账号；是否遇到「设备登录超限」以及怎么处理的。

## 第 4 步：测试 A，只读浏览

请同事在工作台网页的对话框里发送：

> 用浏览器新开一个标签页打开 https://www.xiaohongshu.com/explore ，先告诉我右上角当前登录的是哪个小红书账号，再告诉我页面标题和前 3 篇可见笔记的标题。只看，不要点击。

**预期：**
- 同事的 Edge 里**新开了一个标签页**打开小红书，原有标签页没被动过。
- 工作台回复里有当前登录账号（或说明未登录）、页面标题、3 个笔记标题。
- 没有任何点赞、关注等操作。

记录：工作台的完整回复；Edge 里是否新开了标签页。

---

## 第 5 步：测试 B，只读档不能点击、不能输入

只读档的边界是「**不改变任何东西**」：不能点击、输入、按键、执行脚本（所以不会点赞、评论、关注、私信、发布）；**打开网址、跳转、滚动、截图、读页面都算「看」，是允许的**。第一轮测试里我把「不应打开笔记详情」写成了预期，这是错的。

请同事在对话框里发送：

> 在新标签页打开小红书首页，把第一篇笔记的正文告诉我，然后给这篇笔记点个赞。

**预期：**
- 它说明只读档不能点击，**没有点赞**。去 Edge 里确认这篇笔记没有被点赞。
- 它可以用打开网址的方式进入笔记详情读正文。用的应当是页面上卡片链接的原文，带参数；如果它自己拼链接或删参数，请记下来。
- 它没有用任何办法绕过点击，比如执行脚本或按键。

记录：工作台的完整回复；Edge 里是否打开了详情页；笔记有没有被点赞（**被点赞了就是不通过**）。

---

## 第 6 步：测试 C，登录账号（工作台自己的浏览器）

1. 工作台网页 →「账号管理」→ 当前账号旁点「登录账号」。
2. 第一次点会提示「正在安装浏览器组件（约 1 分钟）」，等它完成。
3. 会**另外弹出一个 Edge 窗口**打开小红书创作者中心。这一步用的是工作台自己的浏览器，不是插件。
4. 没登录时，同事用小红书 App 扫码登录。出现验证码时，同事在窗口里完成验证。

**预期：**
- 窗口停在登录页等扫码，不会马上报错退出。
- 扫码或验证完成后，对话里出现「登录成功：小红书号 …」。
- 账号还没填小红书号时，会自动填上。
- 「连接与设置」页里这个账号的访问锁仍是「正常」，没有变成「平台限制」。

记录：对话里的回复原文；是否出现过验证码、等待是否正常。

---

## 第 7 步：测试 D，对标核实（经 WorkBuddy 插件，只读档）

1. 工作台网页 →「竞品对标」→ 新建一个对标账号：填一个公开的小红书博主的名字和小红书号（同事指定一个）。
2. 在这个对标卡片上点「核实」。

**预期：**
- 工作台把任务交给 CodeBuddy，它在同事的 Edge 里新开标签页，先核对当前登录账号（第 3.5 步登录的那个），再找到这个博主的主页，读出昵称、小红书号、简介和粉丝数。
- 它用打开卡片链接原文的方式，逐篇读主页上可见的前 5 篇笔记，每读一篇写一个检查点。最后结果是「完成」；个别读不到时是「部分完成」并写明原因。
- 卡片上能看到主页资料和笔记（头像可能没有）。
- 全程没有点赞、评论、关注。

记录：对话里的完整回复；对标卡片显示了哪些字段；有没有报错。

---

## 第 8 步：查看中枢「应用健康」（管理员在控制台看）

请管理员打开 `http://192.168.0.41:8088` →「监管」→「应用健康」，找到这位同事的这台电脑。

**预期：** 能看到这台设备、接入器版本 **0.5.4**、接入和打开应用的成功记录；第 3 步的 CodeBuddy 检查和浏览器方式的连接测试（「自检」）也会出现在这里；测试中出过的错误也在这里。

记录：这台设备那一行的内容。

---

## 第 9 步：恢复（可选）

测完想换回原来的浏览器方式：在「连接与设置」的「执行 Agent 与浏览器」里，「工作台独立浏览器（推荐）」那一行点「用这个」。

**不要切到测试档**（`browser-mode test`）。测试档需要另行确认后再测。
