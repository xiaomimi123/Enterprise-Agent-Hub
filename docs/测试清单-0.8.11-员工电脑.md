# 测试清单：小红书运营工作台 0.8.11（员工电脑）

> 适用：工作台 **0.8.11**（已上传中枢）、接入器 0.5.7。在员工电脑上由同事按步骤做，把结果按文末模板写成报告发回。
> 范围：采集节奏与额度、后台 Playwright 采集停用、发布包、打开即换新版本，加上前几版的几项回归。
> 标记：🟢 **不访问小红书**，可以放心做；🟡 **会访问小红书**，有前提条件，没满足就不要做。

## 规则（必须遵守）

1. **品牌号「呷呷寻味小铺」现在在冷静期（至 2026-11-02），且被平台提示过。冷静期内不对它做任何会访问小红书的操作**——所有 🟡 项都先跳过，写「未测：冷静期」。
2. 整个测试**不点赞、不评论、不关注、不私信、不发布**，不要真的用发布包去发一篇笔记。
3. **不要改工作台、接入器的任何文件，不要给它们打补丁。** 发现问题照实记下来，写进报告，由我们这边修。
4. 每一项都记**实际看到的**（截图或原文），不要只写「通过」。和预期不一致就写不一致，继续做下一项。
5. 遇到验证码、「操作频繁」之类的提示：立刻停止，记下来，不要重试。

## F. 真实采集 🟡（现在不要做）

**前提，全部满足才做：** ① 冷静期已结束（2026-11-02 之后）；② 同事本人明确同意；③ 浏览器方式是 WorkBuddy 插件，Edge 里已登录小红书；④ 只采**一个**对标目标。没满足就在报告里写「未测：冷静期」。

| 编号 | 做什么 | 预期 / 要记录 |
|---|---|---|
| F1 | 在卡片里勾上「允许自动采集」，状态应是 ✅ 现在可以采集（在 09:00–22:30 内） | 记录卡片显示 |
| F2 | 点「开始采集待办」，只让它读一个目标，观察 | 采集期间卡片显示「采集中（agent 读页面…）」 |
| F3 | 采集结束后看卡片 | 「今天已读」的笔记 / 主页数和实际读到的一致；「上次访问」是刚才 |
| F4 | 再点一次「开始采集待办」 | 被拒：两次采集至少隔 180 分钟，原因写在提示里；**不会**接着读第二个目标 |
| F5 | 看 `%USERPROFILE%\XHS-Workbench\accounts\default\benchmarks\checkpoints\applied\` 里这一轮的文件名时间戳 | **记下每一篇笔记检查点的时间**（文件名前面的数字是毫秒时间戳，或看文件修改时间），算两篇之间隔了多少秒 |
| F6 | 看状态目录里的 `pace-ledger.jsonl` | 有 `session`、`profile`、`note` 行；**没有** `xsec_token` 之类的参数 |
| F7 | 如果出现「读得太快…已自动停止并关闭采集总开关」 | 这是预期的保护动作，但要记下：当时两篇间隔是多少秒、agent 实际是不是读得很快，**把 F5 的时间戳原样发给我**（阈值 20 秒需要根据真实数据调整） |

停止条件：出现验证码、滑块、「操作频繁」、账号异常提示——立刻停止，在页面上点「遇到验证码/受限，立刻暂停自动访问」，不重试，记录原文。
