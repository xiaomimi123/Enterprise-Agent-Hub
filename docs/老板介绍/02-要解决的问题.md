# 2 为什么要做：企业用 AI 的几个现实问题

下面是企业让员工普遍使用 AI 助手时常见的问题，也是中枢的设计目标。这里是**设计动机**，不是已经测算出的节省金额。

| 问题 | 没有中枢时 | 有中枢时 |
|---|---|---|
| 各用各的，质量参差 | 每个人自己写提示词、自己找资料，同一件事做法不一样 | 公司的做事流程和资料集中维护，所有人的 AI 助手读同一份，改一次全员生效 |
| 资料和边界管不住 | 员工把资料贴给不同的 AI 产品；谁看了什么说不清 | 资料留在公司的知识库里，按岗位和密级过滤；越权被拒绝并记录 |
| 费用不透明 | 各人各付、各自的账号，或共用一个 key，看不出谁花了多少 | 每人一个专属 key，按人、按部门、按模型统计；岗位包设月度额度 |
| 出了问题查不到 | AI 做了什么没有记录，出错靠员工口述 | 每次调用有追踪 ID 和审计；员工电脑上的报错自动回传到控制台 |
| 老板看不到成果 | 只能开会问、翻聊天记录 | 员工上报的成果进入看板，按岗位和个人汇总 |
| 换工具代价大 | 流程绑死在某个 AI 产品上 | 中枢用开放的 MCP 协议对接，AI 助手可以换 |
| 新员工上手慢 | 装环境、配账号、找资料各自摸索 | 一条命令装好并登录；岗位技能和知识库自动就位 |

> 提醒：表里右列描述的是中枢已经实现的机制。效果（例如省了多少时间、质量提升多少）需要在试点期间用真实数据衡量，目前还没有这类统计，本文不给出具体数字。
