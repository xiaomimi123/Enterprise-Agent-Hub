# 4 智能体中枢：能力与老板能看到什么

| 能力 | 解决什么问题 | 老板 / 主管能看到、能做的 |
|---|---|---|
| 统一账号与组织 | 员工用一个公司账号登录，部门即组织结构；停用成员后其 AI 助手的访问在 30 秒内失效 | 在「成员与组织」页建账号、改部门、启用停用 |
| 岗位包与权限 | 不同岗位看到不同的工具和资料，越权调用被拒绝 | 「岗位包」页配置；「审计」页看拦截记录 |
| 技能库 | 公司的做事标准在线编辑、有版本和差异对比、可回滚；本部门修改直接生效，全公司级修改需要审核 | 「技能库」页维护；员工的 AI 助手自动同步 |
| 知识库 | 产品资料、品牌调性、违禁词、历史爆款、制度、售后话术等集中管理，有负责人和复核周期，逾期提醒；发布后可被检索 | 「知识库」页维护，按岗位和密级过滤 |
| 改进建议 | AI 助手发现技能或资料有误时，只能提交建议，不能直接改 | 主管 / 老板审核：采纳、修改后采纳、驳回并说明原因 |
| 模型网关 | 员工的模型调用经过公司网关：专属 key、按人计量、按岗位限额；模型要设价格才计费准确 | 「模型」页、「用量」页：按人、部门、模型看花费 |
| 出图出视频 | 文生图、文生视频、图生视频走统一队列，本机 GPU、第三方 API、H3 网关三条通道可切换，节点掉线自动改派 | 「生成任务」页看队列和结果 |
| 工作成果与日报 | 员工的 AI 助手把「做成了什么」上报；老板的助手可定时拉日报 | 「工作看板」按岗位和个人展示 |
| 审计与可观测 | 每次调用有追踪 ID，同一任务的登录、检索、生成、模型调用串成一条链路 | 「审计」页、总览的实时活动 |
| 应用分发与健康 | 应用由中枢发布、校验后分发；员工电脑上的安装和运行错误自动回传，带错误码和处理办法 | 「应用」页、「应用健康」页 |

## 4.1 对接方式：开放的 MCP 协议

中枢本身是一个标准的 **MCP 服务**（让 AI 助手调用外部工具的开放协议）。凡是支持 MCP 的 AI 助手都能接入：已实测 WorkBuddy 和 CodeBuddy CLI，Hermes 做过早期验证；Cursor、Claude 桌面版的配置写入已支持，尚未实测。员工只需要运行一条安装命令，接入器会自动登录、写好配置、同步岗位技能。

连上之后，助手可使用的工具包括：查询自己的身份和岗位、读取技能、检索知识库、出图和出视频、打开公司应用、上报工作成果、提交改进建议；老板和主管还有「团队成果汇总」。管理类操作（成员、模型价格、岗位包）不在其中，只能在控制台里做。
