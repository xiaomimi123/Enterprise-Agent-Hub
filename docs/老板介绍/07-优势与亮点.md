# 7 核心优势与亮点

| 亮点 | 为什么重要 | 做到什么程度 |
|---|---|---|
| 权限在服务端强制执行 | 不靠提示词约束 AI；即使有人诱导 AI「忽略限制」，越权调用也会被拒 | 已实现，所有工具入口统一判定；知识库内容作为「数据」返回，并标注不可信 |
| 员工的 AI 助手可以换 | 不绑定某个厂商；工具换代时流程和资料不丢 | 通过开放协议接入；WorkBuddy、CodeBuddy 已实测 |
| 公司的做事标准可迭代 | 标准不是写完就扔：AI 在使用中提建议，人审核后生效，每次都有版本可回滚 | 技能库与知识库有版本、差异对比、审核流程 |
| 成本有账可查 | 模型费用可以按人、部门、模型统计和限额 | 已实现；花费按当前配置的价格重新计算，避免价格没设好时统计虚高 |
| 装机不靠运气 | 员工电脑环境千差万别，装不上是最大的落地阻力 | 一条命令安装；装前自检并给出原因；运行环境从中枢下载固定版本；在全新 Windows 虚拟机上完整走通 |
| 升级可控 | 员工电脑上的接入器会自动更新，发错版本影响所有人 | 已做灰度发布与回滚机制：先给指定几人，观察后再放量；出问题可让电脑退回旧版本 |
| 问题自动被看见 | 员工遇到报错通常不会主动汇报 | 报错自动回传，带错误码和处理办法；老板看板上看到版本、系统和成功率 |
| 工程质量有保障 | 两周高速迭代最怕改一处坏一处 | 后端 445 项、前端 16 项自动化测试；提交前和 CI 配置了统一检查；关键口径（在线、花费）有一致性测试 |
| 开源组件优先 | 减少自研和维护负担 | 身份、模型网关、知识检索、生图使用成熟开源组件，自研聚焦权限、治理、调度、计量和集成 |
| 新岗位接入成本低 | 要让每个岗位都有自己的 AI 应用 | 有应用接入指南和接入说明模板，控制台按应用自动展示 |

## 7.1 与「员工各自使用 AI 工具」的对比

| 维度 | 员工各自使用 AI 工具 | 使用中枢 |
|---|---|---|
| 标准与资料 | 各自准备，难统一 | 公司统一维护，自动下发 |
| 权限与数据 | 靠自觉 | 服务端强制，越权留记录 |
| 费用 | 分散、不透明 | 按人计量、可限额 |
| 过程与成果 | 看不到 | 审计、看板、健康数据 |
| 换工具 | 流程要重做 | 开放协议，助手可换 |
| 前期投入 | 低 | 需要部署和维护中枢（见第 9 节的风险） |
