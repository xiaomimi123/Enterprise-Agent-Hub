# 9 现状、验证情况与风险

本节如实说明哪些已经验证、哪些还没有，避免对成熟度产生误判。

## 9.1 已验证

| 项目 | 验证方式 |
|---|---|
| 中枢后端 | 445 项自动化测试通过；关键流程用真实登录和真实接口跑过 |
| 控制台前端 | 类型检查、代码检查通过；16 项页面冒烟测试（登录、总览、成员、应用、接入方式）；应用页和接入方式页由人在浏览器里看过 |
| 员工电脑安装 | 在全新的 Windows 11 虚拟机上从零完整安装并使用；含安装前自检、运行环境下载、快捷方式与图标、老版本升级 |
| 模型与计量 | 用真实网关和临时 key 验证了「工作台任务经过中枢模型」「调用在数秒内计入在线状态」；花费重算后本月数字从虚高的约 6800 元回到约 530 元 |
| 知识库检索 | 文档已索引并可检索（曾因本机端口被系统保留而中断，已修复并写入文档） |

## 9.2 尚未验证或有限制

| 项目 | 说明 |
|---|---|
| 真实员工电脑上的全部场景 | 部分功能（如工作台在线心跳、接入器自动更新）只在隔离环境验证，真实员工电脑上的表现仍需观察 |
| macOS | 安装前自检、运行环境包只在 Windows 上验证过 |
| 云端部署 | 目前运行在本机 Docker 环境；备份与恢复、监控告警、密钥轮换等上云前的运维基础尚未做 |
| 小红书平台风险 | 只读与节奏控制降低但不能消除被平台限制的风险 |
| 业务效果 | 还没有「节省多少时间、内容质量提升多少」的统计，需要试点期间收集 |
| 自动化检查 | CI 工作流已写好，但还没有在代码托管平台上真正运行过 |

## 9.3 主要风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 依赖第三方 agent 工具 | WorkBuddy、CodeBuddy 的沙箱、登录和浏览器插件行为会变，曾导致安装和登录问题 | 安装前自检；错误自动回传；不绑定单一工具；文档沉淀已知的坑 |
| 单点运行 | 中枢目前在一台机器上，宕机则员工的助手暂时用不了中枢能力 | 上云前补备份、监控；员工端对中枢不可达做了降级 |
| 内容质量依赖知识库 | 知识库资料不全，AI 输出会偏 | 知识库有负责人和复核周期；等待产品资料补齐（冲剂 / 饮料） |
| 维护投入 | 平台需要持续的开发与运维 | 通用能力已沉淀，新岗位接入有规范；开源组件减轻自研 |
