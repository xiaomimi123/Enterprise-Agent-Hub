# 部署清单（阶段 0 → 客户现场）

> 给「把系统跑进客户机房」的人照着做。原则：**所有服务集中在一台中枢服务器上，员工电脑和 GPU 机器不装任何中枢组件**。

## 部署形态

| 形态 | 中枢服务器 | GPU 节点 | 适用 |
|---|---|---|---|
| **A · 全部在客户内网**（默认） | 客户台式机 | 客户的 N 卡机器 | 正式交付。数据不出内网，钉钉内网可访问 |
| **B · 中枢上云 + GPU 节点外接** | 租用云服务器（公网 IP） | 任意能装 ComfyUI 的机器（Windows 也行），经隧道接入 | 内部试用 / 演示期，客户机房没就绪时先跑起来；正式交付时同一份代码改 `.env` 平移回内网 |

代码对两种形态无感知——所有地址都在 `.env` 里（中枢地址、MCP 地址、GPU 节点地址），换形态只改配置。**形态 B 的额外要求见第 6 节。**

## 先分清三类机器，各装什么

| 机器 | 数量 | 要装的东西 | 不装什么 |
|---|---|---|---|
| **中枢服务器**（台式机，无需显卡） | 1 | Docker + 本仓库。`make up` 会把全部服务作为容器启动：**Casdoor（身份/钉钉登录）、New API（模型网关）、PostgreSQL、Redis、控制台前后端、MCP Server、模型代理、GPU 调度**，可选 RAGFlow | — |
| **员工电脑**（每人一台） | ~50 | 只装两个东西：[Hermes Agent](https://github.com/NousResearch/hermes-agent) 和员工端接入器（`agent/hub_agent.py`，需要 uv）。登录是在**浏览器里**扫钉钉码，跳到中枢服务器上的 Casdoor 完成的 | 不装 Casdoor，不装数据库，不装任何中枢服务 |
| **GPU 机器**（带 N 卡） | 1 | NVIDIA 驱动 + ComfyUI + 封面工作流用的模型文件 | 不装 Casdoor，不装 Python 之外的东西；中枢通过网络调它的 HTTP 接口 |

一句话回答常见疑问：**Casdoor、New API、数据库全部只在中枢服务器上**；员工电脑上只有 agent 和接入器，甚至不需要一个多余的后台进程（接入器用完即退）。

## 0. 客户侧前置（最早发出，卡在客户手里的）

- [ ] 钉钉开放平台建「企业内部应用」，开通扫码登录和通讯录只读，拿到 **AppKey / AppSecret**（中枢服务器配 Casdoor 钉钉 Provider 时填）
- [ ] 两个测试账号：一个运营部、一个财务部（测越权）
- [ ] 确认台式机配置：**8GB 内存可跑全套（不含 RAGFlow）；要接 RAGFlow 则 ≥16GB（建议 32GB）、磁盘 ≥100GB**、Ubuntu 22.04+ 或同类
- [ ] 确认 GPU 机：显卡型号/显存、能装 NVIDIA 驱动、与中枢服务器网络互通
- [ ] 真实模型的 API key（哪家便宜用哪家，New API 里配渠道；不配则先用本地部署的开源模型或暂缓）

## 1. 中枢服务器（约 30 分钟 + RAGFlow 镜像下载）

```bash
# ① 装 Docker + Compose v2（Ubuntu）
curl -fsSL https://get.docker.com | sh

# ② 拿代码
git clone <仓库地址> && cd 企业agent中枢/hub

# ③ 生成配置，改两处地址
make env
vim .env        # HUB_HOST=<台式机局域网IP>  CASDOOR_ORIGIN=http://<同一IP>:8000

# ④ 启动 + 初始化（生产用 bootstrap，不要用 bootstrap-demo）
make up
make bootstrap  # 初始化 Casdoor（组织+三个登录应用）和 New API（管理员+访问令牌），凭证写回 .env
```

**验证**（每步过了再下一步）：
- [ ] `make ps` 全部 healthy；浏览器开 `http://<IP>:8088` 能登录控制台（组织管理员）
- [ ] `http://<IP>:8000` 能看到 Casdoor 登录页

### 1.1 接钉钉（需要客户的 AppKey/Secret）

- [ ] Casdoor 管理后台（`http://<IP>:8000`，`built-in/admin`）→ Provider 添加钉钉（Client Key/Secret = AppKey/AppSecret，类型 DingTalk）
- [ ] 企业组织里挂上该 Provider 并开启扫码登录；用测试账号扫码登录一次确认部门识别正确
- [ ] 生产环境保持 `HUB_AGENT_PASSWORD_LOGIN=false`（默认就是），员工端只走扫码

### 1.2 接真实模型渠道

- [ ] 台式机本机开 New API 后台 `http://127.0.0.1:3001`（`hubadmin`，密码在 .env）→ 渠道管理 → 添加真实渠道
- [ ] `.env` 的 `HUB_DEFAULT_MODEL` 设为渠道里的模型名，`make up`
- [ ] 控制台「岗位包」里把各岗位的「可用模型」勾上真实模型名（员工 key 的白名单来自这里）

### 1.3 接 GPU 机器（见第 3 节后回来）

- [ ] `.env` 的 `HUB_GPU_NODES` 填 `gpu-01|GPU-01 设计部工作站|http://<GPU机IP>:8188|<显卡型号>`，`make up`
- [ ] 控制台「GPU 节点」页显示在线；发一个封面任务验证出图

### 1.4 接 RAGFlow（可选，16GB 内存才做）

```bash
make ragflow-up          # 拉约 10GB 镜像；Linux 需 vm.max_map_count=262144（脚本会提示）
make ragflow-bootstrap   # 灌 vault/ 知识库，API key 自动写回 .env
vim .env                 # RAGFLOW_ENDPOINT=http://<IP>:9380
make up
```

不接也不影响使用（检索自动回退本地关键词级）。

## 2. 员工电脑（每人 10 分钟）

```bash
# ① 装 Hermes Agent（官方安装方式）→ hermes 命令可用
# ② 装 uv，然后登录（生产环境浏览器钉钉扫码，没有密码参数）
uv run agent/hub_agent.py login --hub http://<中枢IP>:8088
# ③ 日常使用
uv run agent/hub_agent.py chat          # 进入对话；-q "..." 单发一条
```

登录后接入器自动：领取专属模型 key 和额度 → 下载岗位包里的技能 → 生成本机动作上限（只读/需确认）→ 写文件限制在工作区 `~/Documents/中枢工作区`。

**验收**：能对话、能查知识库；管理员的控制台「成员」页该员工显示「在线」；审计日志出现他的链路。

## 3. GPU 机器（约 20 分钟 + 模型下载）

> Windows 机器或不在客户内网的机器（形态 B）见第 6 节，接入步骤相同、多一步隧道。

```bash
# ① NVIDIA 驱动（nvidia-smi 正常）
# ② ComfyUI
git clone https://github.com/comfyanonymous/ComfyUI && cd ComfyUI
pip install -r requirements.txt
# ③ 封面工作流的底模：把 sd_xl_base_1.0.safetensors（或 .env 里 HUB_COMFY_CHECKPOINT 指定的模型）
#    放进 models/checkpoints/
python main.py --listen 0.0.0.0 --port 8188
```

- [ ] 防火墙放行 8188（只对公司内网）
- [ ] 中枢 `curl http://<GPU机IP>:8188/system_stats` 通
- [ ] 回中枢登记节点（见 1.3），控制台发一个封面任务出图即验收

## 4. 上线验收清单（一次性跑完）

- [ ] 运营测试账号：登录 → 查知识库 → 生成封面，全链路通
- [ ] 财务测试账号查运营知识库被拒，审计留「拦截」记录
- [ ] 控制台审计日志能打开任一员工的完整链路（含模型 token 数）
- [ ] 控制台把某岗位额度清零 → 该岗位下一次模型调用立即失败；恢复后正常
- [ ] New API 后台能看到按人计量的用量；控制台「用量与成本」数字一致

## 5. 日常运维

| 事项 | 做法 |
|---|---|
| 升级 | 中枢服务器 `git pull && make up`（数据都在 `hub/data/`，升级不动数据）；员工端 `git pull` 拿到新版接入器即可 |
| 备份 | `hub/data/`（含生成的图片）、`hub/logs/`、`hub/.env`、仓库里的 `skills/ vault/ gpu-node/workflows/` |
| 看日志 | `make logs`（全部服务）；单服务 `docker compose logs -f console-api` |
| 外网访问 | 当前无 HTTPS，仅限公司内网。要外网时前面加反向代理配证书，`.env` 里各地址同步改 |

## 6. 形态 B：中枢上云 + Windows 电脑做 GPU 节点

### 6.1 云服务器（中枢）

- 配置：**2 核 4GB 起步**（不含 RAGFlow）；要接 RAGFlow 则 4 核 16GB。带宽按结果下载估：生图 3 张 PNG（约 5MB/任务）走中枢中转（GPU → 中枢 → 员工），日常 5Mbps 够；以后生视频再提
- **公网上必须先做 HTTPS**：控制台会话、员工令牌、模型 key 都走公网。在云服务器上加一层 Caddy/Nginx 反向代理（自动证书，80/443 → console-web 8088、MCP 8200），然后 `.env`：`CONSOLE_PUBLIC_URL` / `CASDOOR_ORIGIN` / `HUB_MCP_PUBLIC_URL` 全部改为 https 地址，`HUB_COOKIE_SECURE=true`，员工端 `--hub` 填 https 地址
- New API 端口（127.0.0.1:3001）和管理用端口**不要对公网开放**，管理时用 SSH 隧道连上去操作
- 数据在公有云：知识库、审计日志出内网，演示/内部试用可行，正式交付前跟客户确认合规要求（平移回形态 A 只是改 `.env` + 迁数据库）

### 6.2 Windows GPU 节点

ComfyUI 原生支持 Windows（portable 包或 git + pip），中枢只用它的 HTTP 接口，系统是什么无关紧要：

- [ ] 装 ComfyUI，把 `HUB_COMFY_CHECKPOINT` 指定的模型放进 `models/checkpoints/`
- [ ] 启动：`python main.py --listen 0.0.0.0 --port 8188`（portable 包用 run_nvidia_gpu.bat）
- [ ] **开机自启 + 不休眠**：电源计划禁睡眠；用 NSSM 把 ComfyUI 注册成 Windows 服务（或计划任务开机启动）
- [ ] 远程维护：装 ToDesk/向日葵；RDP 3389 不要暴露公网

**接入方式（三选一，前两种推荐）**——红线：ComfyUI 没有鉴权，8188 绝不能直接暴露公网：

| 方式 | 做法 | 中枢侧 HUB_GPU_NODES 填 |
|---|---|---|
| Tailscale 组网（推荐） | 云服务器和 Windows 机都装 Tailscale，登录同一账号 | `http://<Windows机的100.x地址>:8188` |
| WireGuard 自建 | 云服务器做端，Windows 连入 | 同上（WireGuard 网段地址） |
| frp 反向隧道 | Windows 跑 frpc，把 8188 映射到云服务器本机 | `http://host.docker.internal:8188`（compose 已配 host-gateway 映射，容器可访问宿主机端口） |

填好后 `make up`，控制台「GPU 节点」页看到在线即接入成功。

### 6.3 显存与能跑什么（开源模型，量化后）

| 显存 | 生图 | 生视频 |
|---|---|---|
| 8–12GB | SDXL 舒适；FLUX(fp8) 可跑 | 仅小模型（如 Wan 1.3B 量化），分辨率/时长受限 |
| 16GB | 全部主流生图 | 5B 级量化视频模型可跑 |
| 24GB（3090/4090） | 无压力 | 14B 级（Wan2.x fp8 等）主力档 |

拿到具体显卡型号后按上表定岗位包里开放哪些能力。

## 7. 生视频（下一个开发项，待 GPU 节点就绪）

调度链路完全复用（队列、审计、下载签名），需要新增的只有三小块：

1. 工作流模板：`gpu-node/workflows/` 加视频工作流（t2v/i2v），占位符同封面
2. 超时按工作流区分：现在写死 90 秒（封面），视频任务分钟级——`gpu.py` 把等待时长挪进工作流注册表；员工端继续用 `get_cover_task` 式轮询（工具名相应加 `get_video_task` 或参数化）
3. 结果类型：`/api/files/...` 目前写死 `image/png`，要按扩展名返回 mp4；下载链接 TTL 不变

## 已知边界（阶段 0）

- 员工端没有安装包/自动更新（阶段 1 做），目前手动装 Hermes + 接入器
- 钉钉侧只做登录和组织同步的配置；通讯录定时同步、组织异动自动回收权限在阶段 1
- 外部智能体（二级接入）的 MCP 入口已就绪但默认未开放
