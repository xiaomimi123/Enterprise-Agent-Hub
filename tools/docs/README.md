# 《开发与架构文档》生成工具

把 `docs/架构文档/*.md` 生成 Word 和 PDF（`docs/三年级六班集团-企业智能体中枢-开发与架构文档.docx` / `.pdf`）。源文件是 Markdown，**要改文档就改源文件再重新生成**，不要直接改 docx / pdf。

```bash
cd tools/docs
npm install        # 第一次：docx、puppeteer-core、pdfjs-dist、pdf-lib（devDependency 性质，node_modules 不入库）
node build.mjs     # 同时生成 docx 和 pdf；也可以 node build.mjs docx 或 node build.mjs pdf
node preview.mjs ../../docs/三年级六班集团-企业智能体中枢-开发与架构文档.pdf <输出目录> 1 2 10   # 把某几页渲染成 PNG，目视检查版式
```

PDF 需要本机有 Chrome 或 Edge（`build.mjs` 里 `chromePath` 按顺序找）。

## 源文件约定

- 文件按名字排序拼接：`00-封面.md` 是封面信息（`键：值` 一行一项，含「文档版本」「发布日期」等），`01-…` 到 `22-…` 是章节。新增章节就加一个按序号命名的文件。
- 支持的 Markdown 子集：`#` / `##` / `###` 标题（一级标题 = 章，从新的一页开始）、段落、`- ` 列表和 `1. ` 编号列表（两层）、`|` 表格（列宽按内容长度自动分配）、`> ` 提示框、```` ``` ```` 代码块（语言后面可以写一段说明，作为代码上方的路径 / 标题）、`![图题](文件)` 图片（`.png`，或 `.svg`——构建时会渲染成 2 倍 PNG）、行内 `**粗体**` 和 `` `代码` ``。
- **代码片段不要手抄**，用指令从源码里取，保证和代码一致（函数不存在构建会直接报错）：
  - `{{code 路径::函数名 | 说明}}`：取 Python 顶层函数或类（含装饰器），可加 `max=行数` 限制长度；
  - `{{code 路径#起始行-结束行 | 说明}}`：按行号取（源码一改行号就会漂，尽量少用）。
- 目录由标题自动生成：Word 里是带内部链接的目录（没有页码，用导航窗格），PDF 里是带页码的目录（先排一遍找出每个标题在第几页，再把页码填回去）。

## 已知限制

- Word 版本在没有 Word / LibreOffice 的机器上无法渲染预览，只做了结构检查（所有 XML 部件可解析、标题 / 表格 / 书签 / 图片数量）；版式以 PDF 为准。
- PDF 封面的页眉页脚是在第一页上盖白条隐藏的（Chrome 的页眉页脚模板不能按页关闭），所以封面背景必须是纯白。
